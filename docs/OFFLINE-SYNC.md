# MOTO TECH — безопасная синхронизация после потери интернета

Добавлен независимый модуль `docs/offline-outbox.js` на IndexedDB. Он пока **не включён в опубликованную систему**: нельзя автоматически перехватывать все Supabase-запросы, не зная текущей схемы БД и проверок прав.

## Правила
- Сохранение в офлайне: сначала успешная запись в IndexedDB, затем сообщение «Сохранено на этом устройстве, ожидает синхронизации».
- Повторно отправляем только безопасные поддержанные операции, с постоянным UUID операции. Сервер обязан проверять UUID, роль, принадлежность заказа и версии записей; повторная отправка не должна создавать дубль.
- Конфликт (другой сотрудник изменил ту же запись) — статус «Требует проверки», без автоматической перезаписи.
- Непрошедшие проверки прав действия не повторяются до бесконечности.
- После возврата сети проверять серверную доступность и действующую авторизацию. Сигнал browser online сам по себе не означает, что Supabase доступен.
- Не сохранять в локальную очередь PIN, пароли, платёжные реквизиты; для общих/чужих ПК нужна отдельная политика шифрования и очистки.
- Фотографии/файлы: отдельная очередь Blob в IndexedDB, контроль объёмов, повторная отправка в Storage с уникальными ключами, затем привязка к заказу только после подтверждения загрузки.
- Новые заказ-наряды/платежи/удаления пока НЕ разрешены офлайн: они требуют серверной атомарности и отдельного тестирования.
- Индивидуальная очередь для идентификатора пользователя и устройства. После смены учётной записи нельзя синхронизировать данные предыдущего сотрудника под новой сессией.

## Для внедрения
1. Найти и сверить актуальный опубликованный workspace.html (в main его нет) и схему Supabase.
2. Подготовить серверную операцию с проверкой UUID, роли, версии, запретом дублей и RLS.
3. Подключить `createOfflineOutbox({scope,send,onStatus})` в подтверждённые формы, показывать счётчик ожидающих и конфликтов.
4. Протестировать сеть выключена → 2 правки → восстановление → ровно 2 применения; повторный запуск → 0 дублей; смена пользователя и конфликт с другим механиком.
5. Только после тестирования отдельно включить offline-фотографии и создание заказ-нарядов.

Текущая реализация — **основа**, а не гарантия работы всей системы офлайн.
